## Project Workflow

Primary command:

```powershell
node .\workflow\run_report.mjs --send-dingtalk
```

The workflow order is:

1. Collect web logistics data from `https://xy.ele.me/cddp`.
2. Verify the web selection and key logistics rates with PaddleOCR using `workflow/verify_web_ocr.py`.
3. Collect MuMu ADB trade and marketing data.
4. Validate data ranges and history consistency.
5. Export XLSX and PNG.
6. Upload the PNG to Cloudflare R2.
7. Send a DingTalk webhook markdown message containing the R2 PNG URL.
8. Archive the run.

Use `--no-send-dingtalk` for dry runs.

## Web Collection Rules

- On 盯大盘, select 业务线 by expanding `内网` when present, otherwise the page's actual `内单` node, then select `大网`.
- The selected `大网` state must be recorded in `xlsx_work/mapped_data.json` under `navigation.business_big_network.selected`.
- 妥投率 and 用户T准时率（通用） must be OCR-verified from `output/web_big_board.png` before downstream export or sending.

## Cloudflare R2

R2 credentials are read from environment variables, not committed files:

- `CLOUDFLARE_R2_ACCOUNT_ID`
- `CLOUDFLARE_R2_ACCESS_KEY_ID`
- `CLOUDFLARE_R2_SECRET_ACCESS_KEY`
- `CLOUDFLARE_R2_BUCKET`
- `CLOUDFLARE_R2_PUBLIC_BASE_URL`

The upload module is `workflow/upload_r2.mjs`; it writes `output/r2_upload.json`.

## Presentation Rules

- Final PNG is generated by `xlsx_work/fill_template.mjs`.
- 日环比/周环比 positive values are green; negative values are red.
- Alert values remain red for:
  - 平均预测T > 30
  - 妥投率 < 98%
  - 准时率 < 90%
- The 物流 section does not show rider summary rows; the separate 运力线骑手明细 section keeps the汇总（不含未知） row.
